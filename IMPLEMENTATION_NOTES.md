# Правила реализации этой сессии

- Изменения оформлять небольшими смысловыми Git-коммитами.
- Один коммит должен соответствовать одной законченной фиче или одному
  самостоятельному этапу составной фичи.
- Не смешивать в одном коммите независимые изменения.
- Для составной фичи допустимо несколько коммитов, если каждый из них имеет
  понятную цель и может быть отдельно изучен или отменён.
- Перед каждым коммитом проверять точный staged diff и не включать посторонние
  изменения, которые уже находились в рабочем дереве.
- После реализации сообщить список коммитов и краткое назначение каждого.
